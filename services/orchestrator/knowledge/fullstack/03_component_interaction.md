# 组件交互与契约

## 1. 交互建模

每个关键组件交互必须描述：

```text
组件 -> 用户事件 -> 本地状态变化 -> API / 存储操作 -> 成功反馈 -> 失败反馈
```

示例：

| 组件 | 事件 | 操作 | 成功 | 失败 |
|---|---|---|---|---|
| SubmitButton | onClick | POST /api/v1/orders | 跳转订单详情 | 显示库存不足 |
| ThemeToggle | onChange | 写入 localStorage | 立即切换主题 | 回退旧值 |
| ImportButton | onDrop | 解析 CSV 并调用脚本 | 展示导入摘要 | 标红错误行 |

## 2. 轻量 Web

- 纯前端工具必须明确状态存放位置。
- 不引入后端时，契约不得出现 REST API 或数据库 DDL。
- 如使用 Serverless，必须说明函数触发方式、输入输出和配额限制。
- 必须提供空状态、加载状态和错误状态。

## 3. 全栈系统

- 前端不得直接拼接 URL；统一走 API client。
- 表单提交必须防重复点击，并使用幂等键。
- 后端错误必须转换成用户可理解的提示。
- 长任务使用 SSE / 轮询，不允许前端无限期 loading。

## 4. 脚本自动化

- 入口脚本必须支持 `--help` 或 README 示例。
- 输入输出必须有明确格式（JSON / CSV / 文件路径）。
- 外部 API 调用必须设置超时和重试上限。
- 失败时返回非零退出码，并输出可诊断错误。

## 5. 验收标准

契约必须为每个核心流程提供可验证条件：

```text
给定：用户点击“提交”
当：库存充足
则：创建订单成功，库存减少，页面展示订单号

给定：库存不足
当：用户点击“提交”
则：不创建订单，展示“库存不足”，库存不变
```
