# 完整演示链路 · GIS 应用开发工作流

> 叙事：**这不是低代码产品演示，而是我平时开发一个 GIS 业务应用的默认工作流。**
> 项目已经做到 V0；现场从冻结开始，走完契约 → 生成 → 沙盒 → 圈选修改 → 交付。
>
> 目标公司：苍穹数码（GIS 平台 / 遥感测绘）。
> 建议总时长：**6 分钟**（可压到 5 分钟）。

## 1. 开场（0:00–0:30）

> “我平时接到一个 GIS 业务需求，不会先搭脚手架。我的默认工作流是：
> **先把需求收敛成契约，再在画布上对齐界面，冻结后让 AI 在沙盒里写代码，最后用自然语言圈选修改。**
> 这个测绘任务平台我已经用工作流做到 V0，今天从冻结开始继续往下走。”

指一下顶部：**V0 画布 / Schema 通过 / 确认视觉，进入业务审查**。
不要展开功能清单。

## 2. V0 画布：先对齐，不写代码（0:30–1:40）

依次点四个页面 Tab：

1. **项目总览**：4 张统计卡、任务点位示意图、近期动态、重点项目；
2. **任务看板**：待派发 / 进行中 / 待质检 / 已完成四列；
3. **成果质检**：影像成果列表、合格/返工操作；
4. **影像上传**：拖拽区、上传表单、最近上传。

现场做一个动作：

- 圈选“测绘任务看板”标题，改成「华东测区任务看板」；
- 或者拖拽一张任务卡，调整顺序。

讲解词：

> “V0 阶段只出界面树，不写代码。这样我可以先和业务方对齐，
> 而不是等代码生成完才发现页面结构不对。”

> “页面根是隐式容器，不会作为可删除节点出现在画布上；
> 我只能删组件，不能把整页误删。”

> “地图这里是一张内联 SVG 示意底图，不依赖外部地图 SDK；
> 真实项目里这个位置会换成你们现有的 Cesium / OpenLayers 组件。”

**预期**：改动立即生效，Schema 仍然“通过”。
**兜底**：如果圈选不中，直接用左侧组件库拖一个文本组件演示。

## 3. 冻结与澄清（1:40–2:50）

点击 **确认视觉，进入业务审查**。

**预期**：

- 页面回到工作台，右侧 Architect 面板自动打开；
- 面板显示“全栈系统 / 分析中 / 第 1 轮”；
- 1–2 个澄清问题出现，例如：
  - “「成果质检」里的合格/返工点击后后端怎么处理？”
  - “「影像上传」拖拽文件后，文件与元数据如何落库？”

回答方式：

- 单选题：选包含 **REST CRUD + 数据库表** / **JWT + MySQL** 的选项；
- 自由文本“数据实体”填：

```text
Project(id, name, region, manager, status, progress)；
Task(id, projectId, title, assignee, deadline, status)；
Deliverable(id, taskId, fileName, uploader, uploadedAt, qcStatus)；
QCRecord(id, deliverableId, reviewer, result, comment)
```

- 自由文本“业务动作”填：

```text
项目经理创建项目 -> 拆分并派发任务 -> 作业员上传影像成果 ->
质检员审核并标记合格/返工 -> 项目总览更新进度
```

点 **提交回答并继续**，直到《实施契约》出现。

讲解词：

> “这一段不是让模型自由发挥，而是把‘要做什么、存什么、谁来操作’问清楚。
> 不确定的需求在契约阶段收敛，后面才不会反复返工。”

**兜底**：DeepSeek 超过 2 分钟没出契约，先把当前画面留着讲架构图；
或切“本地演示”重开一次。

---

## 4. 契约确认（2:50–3:40）

《实施契约》出现后，展示四个标签页：

- **概览**：技术栈 React + Vite / Spring Boot / MySQL；
- **接口**：API 列表；
- **数据库 DDL**：Project / Task / Deliverable / QCRecord；
- **实施路径**：数据库 → 后端 API → 前端 → 验证。

质量分级已在开始对话前选择（L2 标准），确认契约时不再重复询问。

点击 **确认契约，进入生成**。

**预期**：状态变为“已确认”，出现 **🚀 生成应用（CodeGen）** 按钮。

讲解词：

> “契约一旦确认，UI Run 才会被放行；没确认之前，后端 release 会返回 409。
> 这是项目级门控，防止前后端各做各的。”

## 6. Direct Ops 圈选修改（4:40–5:30）

在 live 画布上：

## 9. 面试官高频追问

**Q：地图是你们自己画的吗？**
> 不是。当前是内联 SVG 示意底图，用来验证业务壳和交互；真实项目接你们现有的 Cesium / OpenLayers 组件。平台的价值在业务外壳、后台 CRUD、交付闭环，不是替代 GIS 引擎。

**Q：能不能直接改我们老系统？**
> 存量模式当前是只读投影 + 后端增量；前端 AST 直改是下一阶段。今天演示的是新建项目的完整闭环。

**Q：为什么不用 Cursor / v0？**
> 直接生成解决“从 0 到 1 写一版”；我解决“从 1 到 N 可控地改”。契约、门禁、沙盒、回滚、源码身份，是交付环节需要的。

**Q：有没有复用 GeoAI 开源方案？**
> 有。本地 `knowledge/geoai_reuse/catalog.md` 收录了 8 个项目：
> TorchGeo、Raster Vision、eo-learn、opengeos/geoai、geoai.js、golem、
> QGIS-SamGeo、geospatial-ml 资源清单。Architect 的 RAG 已验证 GIS 查询
> Top-4 命中该目录；契约会要求给出 REUSE / ADAPT / BUILD 建议和许可证，
> 但不会自动安装或执行仓库代码。

**Q：数据安全怎么办？**
> 所有生成代码只在 Docker 沙盒执行；当前没有 gVisor，也未上云，这是明确的下一阶段。生产会换成独立沙盒节点 / K8s + gVisor，并支持私有化部署。

## 10. 不要说的话

- 不要说“平台能生成 GIS 地图引擎”。当前地图是示意 SVG 占位。
- 不要说“能直接改你们的老系统前端”。存量模式当前是只读投影 + 后端增量。
- 不要说“生产可用”。鉴权是 Mock，未上云，沙盒没有 gVisor。
- 不要把“本地演示”说成假数据。它仍然走真实的 Supervisor / 沙盒 / Direct Ops，只是代码生成用确定性模板。

## 附录：如果面试官要求“从零生成”

### A. 先开一个干净工作台

```bash
DEMO_STATE=demo-clean-storage.json node docs/demo/open-demo.mjs
```

这会打开一个只有 Mock 登录态、没有预生成项目的工作台。

### B. 从零生成步骤

1. 点右上角 **＋**（新建项目）；
2. 选 **从零开始**；
3. 模型保持 **DeepSeek V3**；时间紧就切 **本地演示**；
4. 空白画布点 **开始创建**；
5. 粘贴下面的目标，先选 **L2 标准**（项目规模 / 质量要求，不可跳过），
   再点 **开始架构设计**；

```text
做一个测绘任务与成果管理平台（Web 管理端）：
1) 项目总览：项目进度统计、任务点位地图（用内联 SVG 示意底图 + 点位标记，
   不要依赖外部地图 SDK）、近期动态；
2) 任务看板：按待派发/进行中/待质检/已完成分列，支持派发给作业员；
3) 成果质检：影像成果列表、质检状态、合格/返工操作；
4) 影像上传：拖拽上传、进度、文件列表。
核心实体：Project、Task、Deliverable、QCRecord；数据持久化到 MySQL。
整体风格简洁、专业，适合测绘行业。
```

6. 澄清问题按第 3 节回答：
   - 单选题选 **REST CRUD + 数据库表** / **JWT + MySQL**；
   - 数据实体和业务动作用第 3 节的文本；
   - 点 **提交回答并继续**，直到进入虚拟画布。

**文档中心与“追加修改需求”里的上传**：

- 想让**第一轮澄清**就用文档：先在面板右上角 **📚 文档中心** 上传，
  再开始架构设计；启用的文档会随 Run 进入 RAG。
- 更贴近日常的是：契约确认后，在 **追加修改需求** 区上传，
  文档会参与本次契约修订。

三种语义判断结果：

| 结果 | 行为 |
|---|---|
| **长期复用**（规范 / 需求 / 术语 / 流程） | 自动加入文档中心，后续 Run 可复用 |
| **一次性 / 反向语义**（仅本次 / 临时 / 看完就删） | 只用于本次，不保存 |
| **没有明确语义** | 等待用户选择：加入文档中心 / 仅本次使用 |

现场对比：

- 上传 `docs/demo/gis-requirements-sample.md` → 判定长期复用，加入文档中心；
- 上传 `notes.md`（内容随便一句）→ 无明确语义，弹出“加入 / 仅本次”；
- 上传“仅本次参考，看完就删” → 判定一次性，不保存。

话术：

> “文档不是无脑入库。系统会先判断它是长期规范还是一次性草稿：
> 长期复用的进文档中心，下次不用重复上传；一次性的只用于本次；
> 判不准就问我。这样用户和 Agent 都不用反复处理同一份文档。”

7. **V0 是草稿，不是最终 UI。** 真实模型下常见情况：
   - 只有 2–4 个页面；
   - 地图位置是一个“SVG点位地图”占位容器；
   - 卡片、表格是描述性文本。

   现场补 1–2 个元素即可，不要试图补完：

   - 选中地图占位容器；
   - 点左侧组件库的 **图片**；
   - 选中新图片节点；
   - 在右侧“图片地址”粘贴 `docs/demo/assets/survey-map.data-uri.txt` 的内容；
   - 地图立即出现在 V0 画布，CodeGen 后也会出现在 live 应用。

8. 然后继续第 3–6 节：冻结 → 契约 → CodeGen → Direct Ops。
