### 1.3 Unknown column 永久止血（commit `d0e396d`）

**生成期**

- `parse_ddl_tables` 按括号配对解析多表 DDL，字段完全隔离；
- `core_table_for_contract` 按 API 集合资源选择核心业务表，
  排除 `users` / sessions / migrations 等系统表；
- 删除 `users` + `name` 硬编码兜底，缺失 DDL 时使用
  `app_records` + `id/title/created_at`；
- DBACoder 产出 `server/schema.core.json`，BackendCoder 强制读取并绑定；
- `_assert_generated_schema` 写盘前断言 ORM / 迁移 / 契约一致；
- 模板根据 NOT NULL / DEFAULT / UNIQUE 生成默认值，避免
  `Column 'content' cannot be null` 二次 500。

**构建期**

- ConsistencyVerifier 新增 `orm_schema` 维度：
  对比 `server/db.js` 的 `TABLE` / `COLUMN_DEFS` 与
  `server/migrations/001_init.sql` 的真实列；
- 字段漂移产出 `REGENERATE_ORM`，Graph 自动回退 DBACoder，最多 2 次；
- 修复事件标注 `reason=ORM_SCHEMA_MISMATCH`。

**验收期**

- `acceptance_test.py` 增加 ORM/DDL 静态门禁；
- 运行时校验响应 `table` 等于核心业务表；
- 新增断言：核心业务表 GET/POST 不因字段缺失返回 500；
- MySQL 阶段对比 ORM 字段与真实数据库列。
