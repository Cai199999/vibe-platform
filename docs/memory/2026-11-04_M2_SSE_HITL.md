# M2：SSE 流式执行与 HITL 澄清中断（2026-11-04）

## 目标

把同步 Agent Run 升级为可观测、可中断、可恢复的执行流：

- 前端实时展示 Planner / Coder / Verifier 等节点时间轴；
- 意图置信度不足时暂停 LangGraph，向用户追问，再恢复同一状态机；
- 为后续全栈长任务预留 Redis checkpoint 与结构化编辑器接口。

## 核心实现

### Python AI Core

- `ai_core/agent/events.py`：进程内事件总线，负责 seq 单调递增、回放、
  15s 心跳与终态连接关闭。终态事件后若同一 Run 继续产生非终态事件，
  会清除旧 terminal 标记，保证澄清恢复后重连不会提前结束。
- `ai_core/agent/checkpoint.py`：`CheckpointerProvider` 抽象；
  M2 使用 `MemoryCheckpointerProvider`，`RedisCheckpointerProvider` 预留。
- `ai_core/agent/graph.py`：
  - 拓扑 `planner -> clarify_gate -> coder -> applier -> verifier -> evaluator`；
  - 置信度低于阈值时 `clarify_gate` 调用 `interrupt()`，
    先发 `node.finished(paused)` 再发 `clarification.required`，保证暂停帧是
    该连接的最后一帧；
  - 用户答案通过 `Command(resume=...)` 恢复，最多 3 轮。
- `ai_core/agent/service.py`：Run 生命周期、runId 幂等、thread 级 RUN_BUSY、
  后台线程执行与恢复、澄清 TTL/轮次校验、快照与列表查询。
- `ai_core/api/runs.py`：同步兼容接口 + SSE 启动/重放/澄清回答接口。

### Java BFF

- `RunStreamService` 用 WebClient `exchangeToFlux` 异步透传 SSE，
  不阻塞 Servlet 线程；BFF 不重排 seq。
- `RunController` 新增 `POST /runs/stream`、`GET /runs/{runId}/events/stream`、
  澄清答案/快照/列表接口。
- `AiCoreStreamException` + `RunStreamExceptionHandler` 保留上游 4xx 状态与原始 JSON。

### 前端

- `workspace/runStream.js`：fetch + ReadableStream 解析 SSE，记录 lastSeq，
  断线后用 `afterSeq` / `Last-Event-ID` 重放，指数退避重连。
- `WorkspacePage`：SSE reducer 维护 timeline / clarification / patchPreview，
  终态事件落地为 result 并更新标注 Git 坐标。
- `CanvasStage`：澄清问题以气泡形式渲染在对应标注浮层内，
  支持单选、多选、自由文本；回答后 POST 并恢复事件流。
- `RuntimePanel`：删除固定 STAGES 假进度，改为渲染真实节点时间轴；
  暂停时显示等待确认浮层。
