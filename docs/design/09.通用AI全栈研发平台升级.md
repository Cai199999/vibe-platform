# 09. 通用 AI 全栈研发平台升级

> 状态：v1.0（2026-11-11）
> 范围：分级提问、Architect 澄清体验、开发规范 Skill、AI-Native 产物、全栈导入

## 1. 目标与原则

平台已具备生产级全栈代码生成能力。本轮补齐五块“通用研发平台”能力，
核心原则保持不变：

1. **用户只对关键决策负责**：数据库结构、API 契约、系统架构必须确认；
   样式、命名等实现细节由 Agent 自主完成。
2. **跳过澄清只能由用户发起**：AI 不得自行忽略必填字段。
3. **规范是可执行资产**：开发规范以 Skill 形式挂载到 Coder，而不是写在提示词里。
4. **产物自带 AI 能力**：需要 AI 的应用必须生成真实 SDK 调用与密钥配置，
   而非 Mock 文案。
5. **导入即继续开发**：平台导出的全栈包可在沙盒中重新拉起前后端，
   并恢复画布圈选所需的 `data-source` 标记。

## 2. 升级一：全局 Agent 分级提问

### 2.1 领域枚举

在领域层新增 `DecisionImpact`：

| 枚举 | 典型场景 | 行为 |
|---|---|---|
| `CRITICAL` | 数据库表结构、API 契约、系统架构、依赖/鉴权/支付 | 必须 `interrupt` 提问确认 |
| `MAJOR` | 跨模块交互、状态模型、路由结构 | 默认自主执行；仅在显式缺信息（`needs_clarification=true`）时提问，不受置信度影响 |
| `MINOR` | 样式、文案、变量命名、文件内重构 | 静默生成，绝不打断 |

旧的 `CORE_BUSINESS` / `IMPLEMENTATION_DETAIL` 保留为兼容别名：

- `CORE_BUSINESS` → `CRITICAL`
- `IMPLEMENTATION_DETAIL` → `MINOR`

### 2.2 状态契约

`AgentState` 新增：

```python
class DecisionImpact(str, Enum):
    CRITICAL = "CRITICAL"
    MAJOR = "MAJOR"
    MINOR = "MINOR"
```

`plan_decision_impact` 的取值收敛为上述枚举（含旧值归一化）；
`clarify_gate` 仅在 `CRITICAL` 时允许 `interrupt()`。

### 2.3 判定入口

`should_interrupt()` 是唯一中断判定入口，禁止节点内自行判断：

```python
should_interrupt(
    decision_impact=impact,      # CRITICAL / MAJOR / MINOR
    needs_clarification=...,
    confidence_score=...,
    threshold=...,
    mode="auto",                 # auto / always / off
) -> bool
```

纯样式 / 命名需求即使置信度低于阈值，也返回 `False`。

## 3. 升级二：Architect 澄清轮次与“一键采用建议”

### 3.1 轮次上限

`ARCHITECT_MAX_CLARIFICATION_ROUNDS` 默认值由 5 调整为 **10**，同时：

- `ArchitectRunOptions.max_clarification_rounds` 硬上限由 8 调整为 10；
- `ArchitectSnapshotResponse.max_rounds` 默认值同步为 10；
- 前端不再写死 5，由服务端快照下发。

### 3.2 用户显式跳过

请求体新增字段：

```json
{
  "answers": [],
  "comment": "采用建议并跳过剩余提问",
  "adoptSuggestions": true
}
```

语义：

1. `adoptSuggestions=true` 只能由用户在 UI 点击按钮产生；
2. 服务端按每个未答问题的 `defaultValue` / 推荐选项 / 问题类型合成答案，
   并写入 `clarification.answered` 事件，答案来源标记 `source=USER_ADOPTED`；
3. 图状态写入 `adopt_suggestions=True`，`_route_confidence` 直接进入契约生成，
   `_clarify_gate` 不再暂停；
4. **模型输出中不存在该字段**，LLM 无法自我授权跳过；
5. 若仍然缺少必填字段，采用建议时必须给出确定性默认值或明确假设，
   并在契约 `assumptions` 中记录，不能静默丢弃。

### 3.3 前端

`ClarificationForm` 增加次按钮“一键采用建议并跳过剩余提问”，
仅在存在问题时展示；点击后禁用表单并提交上述请求。

## 4. 升级三：Web 开发规范 Skill

新增 `services/orchestrator/config/skills/web_best_practices.skill.md`：

- RESTful 资源命名、HTTP 方法与状态码、统一错误结构、分页/过滤约定；
- 安全编码：参数化 SQL / ORM、输入校验、Bcrypt 密码哈希、最小权限 CORS、
  禁止把密钥写入代码或日志；
- Express + Sequelize 落地示例。

通过 `backend_coder/manifest.json` 强制挂载，Skill ID 为
`web.best_practices`，与 `production.ready` 同时生效。

## 5. 升级四：AI-Native 应用产物

### 5.1 契约字段

`ArchitectContract` / `ContractDraft` 新增：

```json
{ "includeAiCapability": true }
```

判定规则：需求包含 AI 对话、内容生成、简历筛选/分析、图片理解等语义时置为
`true`；纯 CRUD / 展示型应用为 `false`。

### 5.2 生成产物

当且仅当 `includeAiCapability=true`：

- **BackendCoder**
  - `server/package.json` 增加 `openai` 依赖；
  - 生成 `POST /api/v1/ai/chat` 与 `POST /api/v1/ai/analyze`：服务端读取
    `OPENAI_API_KEY`，使用 OpenAI SDK 发起真实调用；
  - 缺少密钥时返回 `503 AI_NOT_CONFIGURED`，不得返回伪造结果；
  - 请求体做长度 / 类型校验，错误统一走 API 错误结构。
- **FrontendCoder**
  - 生成对话区、消息列表、输入框、发送/加载/错误态；
  - 文件分析场景生成上传控件并调用后端 AI 路由；
  - 使用真实 `fetch`，不得在前端硬编码密钥。
- **InfraCoder / 模板**
  - 生成的 `.env.example` 增加 `OPENAI_API_KEY=` 与 `OPENAI_MODEL=`；
  - `DEPLOY.md` 说明密钥由部署平台注入。

## 6. 升级五：全栈导入

### 6.1 输入格式

导入接口支持：

- `.zip`：原有前端工程 / 图片；
- `.tar.gz` / `.tgz`：平台导出产物。

安全约束：拒绝绝对路径、`..` 路径穿越、符号链接、设备文件；
限制条目数、单文件大小与总解压大小。

### 6.2 全栈识别

解压并剥离统一根目录后，满足以下条件判定为 `fullstack`：

- 根目录存在 `package.json`；
- 存在 `server/package.json` 或 `server/index.js`；
- 存在前端入口（`src/main.jsx` / `src/main.tsx` / `index.html`）。

### 6.3 沙盒启动

全栈项目启动命令按顺序：

1. 安装根依赖与 `server/` 依赖；
2. 后台启动 `node server/index.js`（`FULLSTACK_API_PORT`，默认 3000）；
3. 启动 Vite：`vite --host 0.0.0.0 --port 5173`；
4. 若 `vite.config.*` 缺少 `/api` 代理，自动注入指向
   `http://127.0.0.1:<API_PORT>` 的代理配置；
5. 前端 `VITE_API_BASE_URL` 保持同源 `/api`，由 Vite 代理转发。

### 6.4 画布标记恢复

导入完成后执行源码扫描：

- 对 `src/**/*.{jsx,tsx,html}` 的宿主元素注入
  `data-source="imp-<file>-<line>"`（已有标记不覆盖）；
- 在 `src/main.jsx|tsx` 引入运行时兜底脚本（无入口时注入 `index.html`），
  为动态渲染、未命中源码标记的元素生成稳定的层级标记；
- 重新采集页面快照，恢复 `inspect / annotate` 所需的元素定位能力；
- 响应新增 `kind=fullstack`、`services` 与 `dataSourceCount`。

## 7. 兼容性与边界

- 旧检查点中的 `plan_decision_impact` 旧值在读取时归一化，无需迁移数据；
- 旧契约没有 `includeAiCapability`，默认 `false`；
- 旧 zip 导入路径保持不变，新格式走同一 `import_project` 入口；
- 全栈导入不执行包内任意脚本，只运行标准 `npm` / Vite / Express 启动命令；
- 沙盒仍为单容器多进程，不引入多服务编排。
