# 13 · 双轨制项目模式分流（ProjectModeResolver）

> 2026-11-17 · 前置分流与防呆

## 1. 目标

在 Architect 启动前确定项目类型，避免“存量项目被当成新建项目”导致：

- 凭空生成 VisualDocument；
- 凭空生成 DDL 并自检，报“父键不在父表字段”等假错误；
- 对已有前端触发 FrontendCoder / CodeGen。

## 2. 模式定义

```text
NEW_PROJECT
  - 无源码、无 sandbox、未生成；
  - Architect → VisualDocument → 冻结 → CodeGen。

EXISTING_SOURCE
  - 导入项目 / 非空 files / 已有 sandbox / 已生成源码；
  - 源码是唯一事实源；
  - Architect 只做业务审查与后端增量绑定；
  - 禁止 VisualDocument、整页代码、FrontendCoder、CodeGen。
```

## 3. 确定性判定

前端 `apps/platform-web/src/workspace/projectMode.js`：

```text
imported === true                  → EXISTING_SOURCE
template 以 imported- 开头         → EXISTING_SOURCE
generated === true                 → EXISTING_SOURCE
有 sandboxId / sandboxIds          → EXISTING_SOURCE
非内置模板且 files 非空            → EXISTING_SOURCE
其余（空白新建 / 仅内置演示模板）  → NEW_PROJECT
```

后端 `ai_core/domain/project_mode.py`：

```text
source.sandbox_id 非空   → EXISTING_SOURCE
source.files 非空        → EXISTING_SOURCE
否则采用 declared，默认 NEW_PROJECT
```

前端声明只是回退；后端以 source 事实为准，防止绕过。

## 4. UI 强制分流

新建项目必须先选择：

- **从零开始生成** → 创建空白项目，进入 NEW_PROJECT；
- **导入源码分析** → 读取 `.jsx/.tsx/.js/.ts`，创建 imported 项目，
  立即跳转只读投影。

不允许先创建项目、再让 Architect 猜测模式。

## 5. 新建项目两阶段产出

```text
NEW_PROJECT
  → Architect 多轮澄清
  → VISUAL_V0：只输出 VisualDocument（API / DDL / relations 为空）
  → AWAITING_VISUAL_EDIT：自动打开画布，记录 v0 基线
  → 用户离线编辑
  → 冻结：计算 v0 → current delta
  → BACKEND_BINDING：只输出 API / DDL / relations，复用冻结虚拟树
  → 契约确认
  → FullstackGraph：后端 Agent + 冻结虚拟树 CodeGen
```

约束：

- `VISUAL_V0` 不生成后端字段，避免 UI 语义未定时凭空生成 DDL；
- `BACKEND_BINDING` 不重新生成 VisualDocument，只读取冻结树 + delta；
- 最终契约携带冻结 `visualDocument`，CodeGen 直接使用；
- delta 只包含新增 / 删除 / 移动 / 修改节点及新增交互/绑定；
- 槽位：V0 只要求 `ui.layout` / `ui.primary_flow`；后端绑定不再问
  `ui.layout`。

## 6. 多页面与高保真

- `VisualDocument.pages`：`[{pageId, path, title, root}]`，`root` 镜像当前页；
- `metadata/activePageId` 记录当前页；页面根必须是 `page` 节点；
- `VisualInteraction.targetPageId` 支持 navigate 页面跳转；
- 画布顶部页面 Tab：切换、新增页面；当前页独立编辑；
- 高保真预览：真实 HTML/CSS 渲染设计令牌、页面 Tab 与 navigate；
- V0 生成：
  - `frontendRoutes` 多路由时确定性生成多页；
  - 首页承载完整组件，其余页面先给 header + main 占位；
  - Prompt 要求真实文案、示例数据、至少 3 个业务区块；
- CodeGen：
  - 多页编译为 `PageX` 组件 + `VISUAL_PAGES` + 页面导航；
  - navigate 交互生成 `onNavigate(targetPageId)`；
  - 每个节点仍保留 data-node-id / data-source 门禁。

## 7. 存量模式行为

### 5.1 只读投影

- `VisualCanvasPage` 检测到 EXISTING_SOURCE 后自动解析源码；
- 渲染 `ReadOnlySourceCanvas`，不渲染可编辑虚拟画布；
- 不读写 `visualDocumentStore`；
- 提示：`当前为只读分析视图。源码直改（AST）能力尚未开放`。

### 5.2 Architect System Prompt

追加 `【EXISTING_SOURCE 模式 · 最高优先级】`：

- 严禁输出 `visual_document`、整页 JSX/TSX/HTML；
- 不重新设计页面结构，不询问 `ui.layout`；
- 只基于 `source_files` 中的文件树、组件、路由、交互做业务审查；
- 只问后端增量：接口、数据库、鉴权、权限、持久化；
- `visual_document` 必须输出空对象。

### 5.3 契约与校验

- `validate_draft(..., project_mode=EXISTING_SOURCE)`：
  - 跳过 DDL relations 自检；
  - 不强制 `component_interactions`；
- `assemble_contract`：
  - `visual_document = None`；
  - 不从增量 DDL 凭空推导全量 relations；
- `FullstackService._resolve_contract`：
  - 存量项目 `mode=frontend/fullstack` 直接拒绝；
  - 只允许 `backend` 增量模式；
- `audit_contract`：
  - 存量项目跳过 DDL 表 / relations 审计，避免假错误。

### 5.4 生成路径

```text
Architect（业务审查 / 后端增量）
  → 确认契约
  → FullstackGraph mode=backend
      DBACoder → BackendCoder → BuildVerifier → SandboxRestart
  → 不运行 FrontendCoder / InfraCoder / ConsistencyVerifier
```

前端 `handleFullstackGenerate` 在 EXISTING_SOURCE 下自动改走
`handleExistingBackendGenerate`，按钮文案为“生成后端增量”。
