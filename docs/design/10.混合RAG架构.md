# 10. 混合 RAG 架构（Hybrid RAG）

> 状态：v1.0（2026-11-11）
> 范围：本地向量库、BM25 + Chroma 双路召回、RRF 融合、Architect / Planner 接入

## 1. 目标

把原有“纯 Markdown + BM25”知识检索升级为混合 RAG：

- **硬性约束**继续由 Markdown Skill / 规范文档承载，要求可审计、可版本化；
- **软性知识**（企业长文档、API 手册、安全规范）进入本地向量库；
- 不引入 Milvus、Qdrant 等独立外部服务，不增加运维依赖；
- 检索失败可降级，不能成为 Architect / Planner 的单点故障。

## 2. 组件

```text
knowledge/
  fullstack/*.md          ──┐
  enterprise_docs/*.md    ──┴─> 同一语料切块
                                  ├─ BM25 稀疏召回（MarkdownRAGProvider）
                                  └─ Chroma 向量召回（ChromaRAGProvider）
                                            │
                                      RRF 融合（HybridRAGProvider）
                                            │
                                  Architect / Planner 的 Top-K Chunk
```

### 2.1 ChromaRAGProvider

- 使用 `chromadb.PersistentClient`，数据落在 `CHROMA_PERSIST_DIR`（默认
  `data/chroma`，位于挂载的 `/app/data` 下）；
- Embedding 为 Chroma 内置 ONNX `all-MiniLM-L6-v2`，不依赖 PyTorch，
  不需要 API Key；镜像构建阶段预热模型，运行期离线可用；
- 与 BM25 复用同一个 Markdown 切块函数，Chunk ID 为
  `sha1(path + section + content)`；
- 首次检索增量建库：只 upsert 新 Chunk，删除已下线文档；进程重启复用
  已有索引，不重复向量化；
- 只返回 `RetrievedChunk`，不向上层泄漏 Chroma 类型。

### 2.2 HybridRAGProvider

两路查询通过 `ThreadPoolExecutor` 并行发起，各取 `top_k × 3` 个候选，
再用 RRF 合并：

```text
rrf(d) = Σ_source 1 / (k + rank_source(d))，k = 60
```

- 只依赖排名，不混合 BM25 分值与余弦相似度；
- 按 `path + section` 去重，同一 Chunk 被两路命中时累加分数；
- 返回结果 metadata 保留 `retrievalSources / bm25Rank / chromaRank /
  rrfScore`，便于排查与后续评估；
- 单路异常时记录日志并返回另一路结果；两路都失败才抛错。

两路必须索引**同一语料**（`RAG_KNOWLEDGE_ROOT=knowledge`），否则跨语料
排名不可比较，RRF 会让不相关但“本路第一”的结果抢占位置。

## 3. 与现有系统集成

### 3.1 Architect

- `ARCHITECT_RAG_PROVIDER` 默认改为 `hybrid`；
- `ArchitectRunOptions.ragProvider` 允许 `hybrid / markdown / chroma`，
  默认 `hybrid`；前端工作区默认提交 `hybrid`；
- Graph 与 Helper 的检索调用不变，仍通过 `RAGProvider.retrieve()`。

### 3.2 Planner

- `RunExecutionService` 在初始状态注入 `rag_provider / rag_top_k`；
- `_planner` 从画布标注提取查询（用户诉求 + 元素选择器 + 目标文件），
  调用同一 `HybridRAGProvider`，默认 Top-3；
- 检索结果写入 `rag_context / rag_citations`，并追加到计划文本；
- DeepSeek Planner 的 Prompt 增加“企业规范优先、引用需注明章节”的约束；
- 纯拖拽（确定性几何修改）跳过 RAG，不引入无意义延迟。

## 4. 配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `ARCHITECT_RAG_PROVIDER` | `hybrid` | `hybrid / markdown / chroma` |
| `RAG_KNOWLEDGE_ROOT` | `knowledge` | 双路共同索引的语料根目录 |
| `ENTERPRISE_KNOWLEDGE_DIR` | `knowledge/enterprise_docs` | 单独使用 Chroma 时的目录 |
| `CHROMA_PERSIST_DIR` | `data/chroma` | 本地向量库持久化目录 |
| `CHROMA_HYBRID_COLLECTION_NAME` | `knowledge_corpus` | Hybrid 使用的集合 |
| `RAG_HYBRID_RRF_K` | `60` | RRF 平滑常数 |
| `RAG_HYBRID_CANDIDATE_MULTIPLIER` | `3` | 每路候选扩张倍数 |
| `AGENT_RAG_TOP_K` | `3` | Planner 召回数量 |

## 5. 演示与验证

`services/orchestrator/demo/rag_hybrid_demo.py` 对
`knowledge/enterprise_docs/01_security_and_jwt.md` 提问：

1. “我们公司的 API 用什么鉴权方式？”
2. “JWT 过期时间设多久？”

脚本分别打印 BM25、Chroma、RRF 融合的 Top-3 片段与两路排名。

### 5.1 实测记录（2026-11-11）

- 演示文档约 2400 字，切块后 Q1 的 RRF #1 为“二、API 鉴权方式”，
  内容明确给出 OAuth 2.1 与内部 JWT Bearer；
- Q2 的 RRF #1 为“三、JWT 令牌规范”，内容包含“访问令牌有效期
  15 分钟、刷新令牌 7 天”；
- 生产容器默认 `get_rag_provider()` 返回 `hybrid`，两问 Top-3 均由
  `enterprise_docs` 命中；
- Python 单测 **315 项全绿**（新增 9 项覆盖 Chroma 索引、RRF、
  单路降级与 Planner 引用）；
- `python-ai` 镜像构建阶段完成 Embedding 预热，运行期无需联网。

## 6. 边界

- 当前 Embedding 为英文 MiniLM，多语言语义能力有限；中文关键词与短句
  已实测可用，后续可替换为 BGE-M3 等中文模型（接口不变）。
- Chroma 为单机嵌入式模式，未做多副本与独立扩缩容；企业级大规模知识库
  再演进到独立向量服务。
- 导入包中的 `data/fullstack.sqlite` 与本地 Chroma 索引均不进入 Git。
