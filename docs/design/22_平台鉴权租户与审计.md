# 22 · 平台鉴权、租户上下文与审计落库

> 状态：基础实现（2026-11-25）
> 关联：`docs/design/16_平台终极目标与路线图.md` G2

## 1. 目标

把平台从“Mock 鉴权 + 口头租户”推进到可配置的真实鉴权底座：

- OIDC Resource Server 可开关，启用后 API 必须携带 Bearer JWT；
- 租户上下文统一由过滤器解析，供仓储与审计复用；
- 写操作审计真实落到 MySQL，只追加、不更新、不删除。

## 2. OIDC

配置项（`application.yml` / 环境变量）：

```yaml
vibe:
  oidc:
    enabled: ${VIBE_OIDC_ENABLED:false}
    issuer-uri: ${VIBE_OIDC_ISSUER_URI:}
    jwk-set-uri: ${VIBE_OIDC_JWK_SET_URI:}
```

行为：

| 状态 | 行为 |
|---|---|
| `enabled=false`（默认） | 保持 Mock：所有 API 放行，角色由 `X-User-Role` 表达 |
| `enabled=true` + `jwk-set-uri` | 使用 JWKS 校验 JWT |
| `enabled=true` + `issuer-uri` | 通过 OIDC Discovery 校验 |
| `enabled=true` 且两者都缺失 | **启动失败**（fail-closed） |

健康检查 `/api/v1/health/**` 始终公开。

实现：`identity/SecurityConfig.java`、`identity/OidcProperties.java`。

## 3. 租户上下文

- OIDC 启用时优先读取 JWT claim `tenant_id`；
- 未启用或 claim 缺失时回退请求头 `X-Tenant-Id`，缺省 `tenant_local`；
- claim 与请求头同时存在且不一致 → 403 `TENANT_MISMATCH`；
- 校验：1–64 位字母、数字、下划线、短横线；
- 非法值直接 400 `INVALID_TENANT`；
- 生命周期：请求内 ThreadLocal，响应头回写，请求结束清理。

实现：`identity/TenantContext.java`、`identity/TenantFilter.java`。

## 4. 审计落库

表：`vibe_audit_event`

| 列 | 说明 |
|---|---|
| `tenant_id` | 租户 |
| `trace_id` | 全链路 traceId |
| `actor` | `X-User-Id`，回退 `X-User-Role` |
| `method` / `path` / `status` | 请求元数据 |
| `detail` | User-Agent 截断，不含请求体 |
| `created_at` | 数据库时间 |

规则：

- 只记录 `POST / PUT / PATCH / DELETE` 且路径以 `/api/` 开头；
- 不记录请求体，避免客户数据进入审计表；
- 写入失败只告警，不阻断业务（后续可切换 fail-closed）；
- 表按需创建，正式环境应改为 migration 管理。

实现：`audit/AuditEventRepository.java`、`audit/AuditFilter.java`。

### 4.1 审计查询 API

```http
GET /api/v1/audit/events?limit=50
X-User-Role: admin
X-Tenant-Id: tenant_audit
```

- 仅管理员可用（复用 `@IsAdmin` 切面）；
- 按当前租户隔离，`limit` 上限 200；
- 返回 `tenantId / requestId / events[]`，不返回请求体。

## 5. 与生成应用鉴权的区别

- **平台自身**：本节描述的 OIDC/租户/审计；
- **生成应用**：已有独立 JWT + RBAC（`docs/design/19`），两者不要混为一谈。

## 6. 当前边界

- 已支持 JWT claim 回填，但尚未接真实 IdP 联调（Keycloak/Auth0 等）。
- 没有行级权限（RLS）；仓储按 `tenant_id` 显式过滤，但未做数据库级兜底。
- 审计查询 API 已具备，但无导出 / 保留策略 / 分页游标。
- 审计表未纳入正式 migration 版本管理。

## 7. 下一步

1. 为 `projects / runs / contracts / audit` 增加 RLS 或统一仓储过滤。
2. 审计导出、保留策略与游标分页。
3. 用 Keycloak 本地容器做一次真实 OIDC E2E（含 claim 租户）。
