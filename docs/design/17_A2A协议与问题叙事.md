# 17 · A2A 协议与问题叙事

> 2026-11-21 · 目标：在不改变现有执行逻辑的前提下，把 Agent 之间的交接、
> 诊断、修订、验证与升级固化成可测试的协议和可展示的问题叙事。
>
> 本阶段只做「契约 + fixtures + 纯函数」；默认不接入运行时，不改变
> V0 / live 主流程。

## 1. 原则

1. **只做加法**：不改 `a2a.feedback` 既有字段、事件名、发出位置。
2. **默认关闭**：叙事 UI 由 `A2A_NARRATIVE_ENABLED=false` 控制，关掉时行为与现在完全一致。
3. **先契约后实现**：前后端共用同一组 fixtures；先让契约测试绿，再谈 UI。
4. **观察不决策**：叙事只解释“谁向谁提出了什么”，不参与重试/升级决策。

## 2. 允许矩阵

`(fromAgent, toAgent, kind, requestedAction)` 必须命中下表；矩阵外一律
fail-closed，不允许新增“随手发给某个 Agent”的通道。

| Applier | DBACoder | `schema_repair` | `REGENERATE_DB` |

| BackendCoder | Architect | `contract_review` | `REVIEW_CONTRACT` |
| ConsistencyVerifier | Architect | `contract_revision` | `REVISE_CONTRACT` |
| ConsistencyVerifier | Architect | `contract_review` | `REVIEW_CONTRACT` |
| ConsistencyVerifier | DBACoder | `schema_repair` | `REGENERATE_ORM` |

## 3. 事件信封

沿用现有 `a2a.feedback` 字段：

```json
{
  "feedbackId": "a2a_...",
  "runId": "fsk_...",
  "fromAgent": "Applier",
  "toAgent": "BackendCoder",
  "kind": "code_repair",
  "requestedAction": "REPAIR_CODE",
  "summary": "index.js 缺失分页参数校验",
  "evidence": ["src/server/index.js:42"],
  "contractId": "ctr_...",
  "payload": {
    "attempt": 1,
    "maxAttempts": 2,
    "status": "RESOLVED"
  },
  "createdAt": "2026-11-21T05:10:00Z"
}
```

约束：

- `feedbackId` 唯一；重复 id 只保留第一条，并产生 warning；
- `summary` 必填，最多 2000 字；
- `evidence` 是字符串数组；
- `payload.status` 可选，只能是 `RESOLVED / ESCALATED / FAILED`；
- 运行时没有 `status` 时，叙事根据 run 终态推断。

## 4. 问题叙事模型

```json
{
  "steps": [
    {
      "feedbackId": "a2a_...",
      "at": "2026-11-21T05:10:00Z",
      "from": "Applier",
      "to": "BackendCoder",
      "kind": "code_repair",
      "problem": "index.js 缺失分页参数校验",
      "action": "REPAIR_CODE",
      "evidence": ["src/server/index.js:42"],
      "status": ""
    }
  ],
  "loops": 1,
  "terminalReason": "RESOLVED",
  "warnings": []
}
```

前端展示：

```text
问题：index.js 缺失分页参数校验
  ↓
诊断：Applier 判定 CODE_DEFECT
  ↓
交接：Applier → BackendCoder（REPAIR_CODE）
  ↓
处理：BackendCoder 重写分页校验
  ↓
验证：ConsistencyVerifier PASS
  ↓
结论：RESOLVED（loop=1）
```

## 5. 循环与终态

- 修复类 kind：`schema_repair / code_repair / route_repair / contract_revision`；
- 升级类 kind：`contract_revision / contract_review`；
- `runTerminal=SUCCEEDED` → `RESOLVED`；
- `runTerminal=FAILED` 且出现升级类 → `ESCALATED`；
- `runTerminal=FAILED` 且无升级类 → `FAILED`；
- 都没有 → `IN_PROGRESS`。
